# Clawworker Enterprise

### 结构化数据不出本机的 AI 数据分析助手 · 全程同态加密

**让企业用自然语言分析敏感表格与数据库：数值明文留在本地，AI 只见字段不见数据。**

销售 · 财务 · 库存 · 客户 · 人力 —— 问一句,出一份 Excel。

</div>

---

## 这是什么

Clawworker Enterprise 是一套**面向企业的隐私计算数据分析平台**。员工像跟 ChatGPT 聊天一样提问("按大区算每位代表的回款率,导 Excel"),系统在**本机同态加密态**下完成计算,把结果以专业 Excel 交付 —— 整个过程:

- 🔒 **结构化数据明文不出本机** —— Excel、CSV、数据库结果先加密,计算在密文上跑,只有最后授权解密才在本地还原
- 🤖 **AI 零数据上下文** —— 大模型只收到字段名(schema),看不到任何一行真实数据
- 📊 **结果即交付** —— 多 sheet Excel,身份列 + 派生指标 + 图表,中文表头、百分比、档位涂色
- ⏰ **可托管运行** —— 定时任务自动跑,数据放进文件夹就自动刷新,结果加密暂存待你批量解密

适用于对**数据合规、隐私保护、内部管控**有要求的场景:财务核算、销售经营分析、客户洞察、库存优化、私域数据、医疗/金融等受监管行业。

## 核心能力

| 能力 | 说明 |
|---|---|
| **自然语言分析** | 用大白话提问,AI 读字段 → 写代码 → 密态计算 → 出 Excel |
| **同态加密计算** | crypto_toolkit + pandaseal + henumpy + helearn,密文上做分组/比率/统计/回归/聚类 |
| **技能体系(Skill)** | SKILL.md 教学技能(AI 现写代码)+ 固化业务模板(回款率/RFM/账龄/ABC/同比环比/预测...)双层,可拖拽扩展 |
| **解密授权门** | 计算在密态完成后,弹窗确认是否解密展示;拒绝则导出密文版 Excel |
| **定时任务** | 每天/每周/每月/自定义(大白话排程),绑定文件夹自动取最新数据,密态结果累积后批量解密到文件夹 |
| **文档理解** | 附 TXT/Word/PDF 作上下文；正文仅在用户明确确认后发送给所配置的大模型（如“按这份办法里的口径算提成”） |
| **企业数据库** | 管理端统一接入多个 MySQL/PostgreSQL/SQL Server，按用户配置表级和字段级权限；用户端只看到已授权数据 |
| **企业管控** | Admin 后台:账户/证书签发吊销、多 LLM 配置、按模型/用户/日/月的用量与成本统计 |

## 为什么是同态加密

传统"脱敏 / 上云分析"要么损失精度,要么仍把数据交给第三方。Clawworker 用**全同态加密(FHE)**:

```
明文数据  ──加密──▶  密文  ──密态计算(加减乘除/聚合/ML)──▶  密文结果  ──授权后本地解密──▶  Excel
   │                                                                              
   └─ 结构化数据与密钥始终在用户本机,大模型只见 schema；文档正文另行明确确认
```

- **AI 提供"怎么算",不接触"算什么"** —— 大模型生成分析代码 / 选择技能,数据始终是密文
- **密钥本地沙盒** —— sk/evk 存 `~/.agent-system/` 沙盒(0600 权限),证书由企业 Admin 统一签发、可吊销
- **三道安全护栏** —— 解密前授权 · 输出路径白名单 · AI 回复零明文过滤

## 架构

```
┌─ 主机端 (Host · 控制面) ────────┐     ┌─ 客户端 (Client · 数据面 + 执行) ──────┐
│  • 账户 / 证书签发吊销           │     │  • 同态密钥本地沙盒(sk/evk 不出本机)   │
│  • 多 LLM 配置 + 用量统计        │◀───▶│  • 密文文件管理 + 自动加密入库          │
│  • 数据源 / 表字段权限 / 使用审计 │     │  • 授权数据库结果本地加密后分析          │
│  • LLM 代理(只转发,不存数据)  │     │  • Skill 引擎:代码生成 + 安全执行      │
│  • Admin Web UI                 │     │  • 定时任务调度 + 文件夹监控            │
│  本机 HTTP :8442 · 局域网 HTTPS :8443 │     │  • 多 sheet Excel 产品级渲染           │
└─────────────────────────────────┘     │  本机 HTTP :8444                       │
                                         └────────────────────────────────────────┘
        ↑ 结构化分析只传 schema + 用户意图；文档正文仅在用户明确确认后传输 ↑
```

**两进程 + 双面分离**:主机端负责治理(谁能用、用哪个模型、花了多少),客户端负责数据(加密、计算、解密、出表)。LLM 代理在主机端中转,但 Excel、CSV 和企业数据库的任何一行真实数据都不会经过它；用户确认发送的文档正文除外。

## 技术栈

- **隐私计算**:crypto_toolkit(加解密)· pandaseal(密态 DataFrame)· henumpy(密态数值)· helearn(密态机器学习)
- **AI 编排**:代码生成 + AST 安全扫描 + 受限沙盒执行;固化技能兜底;LLM 回环自修复
- **后端**:Python 3.11 · FastAPI · 多 LLM(OpenRouter / OpenAI / Anthropic / 国内兼容)
- **前端**:原生 JS 单页(ChatGPT 风格)· Jinja2 Admin · openpyxl Excel 渲染
- **调度**:croniter · 文件夹监控 · 自然语言排程解析

## 安全与合规

| 维度 | 设计 |
|---|---|
| 数据驻留 | Excel、CSV、数据库数值明文与密钥不出本机；LLM 只见字段 schema。Word/PDF/TXT 正文发送前必须明确确认 |
| 密钥保护 | sk/evk 存本地沙盒,0700 目录 / 0600 文件,路径越权防御 |
| 授权链路 | 证书由企业 Admin 签发,可吊销;吊销后客户端初始化即失败 |
| 解密管控 | 每次解密需用户显式授权(人在回路审批 / Human-in-the-Loop);可选"保留密文"导出 |
| 代码执行 | AI 生成代码经 AST 安全扫描(禁文件/网络/危险调用)+ 受限命名空间执行 |
| 输出约束 | Excel 仅写 `~/Downloads/` 白名单;AI 回复经零明文过滤 |
| 审计 | 用量按模型/用户/日/月统计;定时任务运行历史可查 |

## 当前版本 · v1.7.0

- 管理端与用户端均使用本机回环 HTTP；只有跨电脑的局域网链路使用 HTTPS，避免本机自签证书造成启动失败
- 企业数据库支持多数据源、多用户、表/字段级授权，以及查询超时、行数、并发、频率和使用审计
- 数据库结果到达用户电脑后先本地加密，再进入分析流程；未授权的数据源、表和字段不可见且后端拒绝访问
- 用户端使用 WebView2 独立桌面窗口，保留浏览器诊断入口；覆盖安装会自动修复损坏的旧运行环境
- 后端、前端、任务执行、路径、存储和错误处理已经模块化；522 项自动化测试通过，5 项真实后端条件测试按环境跳过

### Windows 企业部署

发布包分为 `Clawworker-admin-Setup-1.7.0.exe` 和
`Clawworker-client-Setup-1.7.0.exe`。两者均内置 Python 3.11 和各自所需的
最小离线依赖，目标电脑无需预装 Python，也无需联网。管理端安装包需要管理员权限，
用于安装 SQL Server ODBC 运行环境；用户端安装包按需安装 WebView2 和本地密态计算库。
构建时会同时生成 `SHA256SUMS-1.7.0.txt`，用于核对安装包是否完整。

完整构建和安装说明见 [`packaging/windows/README.md`](packaging/windows/README.md)。

## 快速开始

```bash
# 1. 环境(Python 3.11+)
python -m venv .venv && source .venv/bin/activate
pip install -e ".[dev,host,client]"

# 2. 接入同态加密工具链(crypto_toolkit / pandaseal / henumpy / helearn)
#    详见 PROVIDE_ME.md;把企业签发的 sk / evk / user_authorization 放到约定位置

# 3. 启动(两进程)
# 主机端同一进程双监听:127.0.0.1:8442 HTTP + 0.0.0.0:8443 HTTPS
AGENT_BACKEND=real python -m host.gateway

# 用户端仅本机回环 HTTP
AGENT_BACKEND=real uvicorn client.webui:app --host 127.0.0.1 --port 8444
```

- **Admin 后台(本机)**:http://127.0.0.1:8442/admin —— 建账户、签发证书、配 LLM、看用量
- **Host API / 远程 Admin(局域网)**:https://<主机地址>:8443 —— 强制 TLS
- **用户端**:http://127.0.0.1:8444 —— 登录、上传加密数据、提问、出 Excel、设定时任务

### 远程企业数据库模式

管理端可统一连接一个或多个远程 MySQL / PostgreSQL / SQL Server，并按用户或用户组授予表、字段和操作权限。授权后无需逐次审批，未授权的数据源、表和字段不展示且由后端强制拒绝；管理端记录使用人、范围、行数、耗时和结果状态，但不保存结果正文。数据库凭据只在管理端使用 Windows DPAPI 加密保存，不下发到用户端；查询结果抵达用户电脑后先在本地加密，再进入受控数据分析流程，大模型不接收明文数据行。完整边界与接口见下方数据库访问文档。

数据库查询采用受控任务执行：管理员可按数据源配置超时、最大行数/大小、单用户并发数和每分钟频率；用户端显示执行耗时并可主动取消，超时、取消及安全限制都会进入使用记录。

测试:`pytest`(stub 后端)· `AGENT_BACKEND=real pytest`(真实加密)
