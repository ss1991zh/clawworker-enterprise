# 企业数据库访问 · 安全架构与首版接口

## 1. 安全边界

Clawworker 的远程数据库模式与“用户上传本地文件”模式有不同的数据驻留边界：

| 环节 | 本地文件模式 | 远程数据库模式 |
|---|---|---|
| 数据来源 | 用户电脑 | 企业远程数据库 |
| 数据库密码 | 不涉及 | 仅管理端 DPAPI 加密保存，不下发 |
| 管理端是否接触数据行 | 否 | 查询执行与转发期间在内存中短暂接触 |
| 管理端是否持久化结果 | 否 | 默认不落盘，不写普通日志 |
| 大模型是否接触数据行 | 否 | 否；只接收授权后的结构和用户意图 |
| 用户端是否获得数据 | 本机文件原有数据 | 只获得授权查询的结果 |

因此产品承诺应表述为：**业务数据不发送给大模型；管理端不持久化查询结果；数据库凭据不下发到用户端。**

## 2. 数据流

```text
用户端登录 → 获取授权目录 → 提交 SQL/查询意图
→ 管理端重新核验会话与实时权限
→ SQL AST 安全校验 → 强制行数限制
→ 使用管理端只读凭据连接远程数据库
→ 结果经 HTTPS 返回用户端 → 本地分析 / 加密 / Excel
```

权限撤销后下一次目录、预览或执行请求立即失败。用户端页面缓存不能代替管理端权限判断。

## 3. 首版权限模型

```text
用户 → 数据源 → Schema → 表/视图 → 字段 → 操作 → 最大返回行数
```

操作包括：`browse` 浏览结构、`query` 提取、`analyze` 分析、`export` 导出。没有明确权限时默认拒绝。第一版禁止 `SELECT *`，要求显式列名。

## 4. SQL安全规则

- 只允许单条 `SELECT`、只读 CTE 和集合查询。
- 禁止写入、DDL、事务、管理命令和多语句。
- 按 AST 核验每一张物理表和每一个字段。
- 禁止文件读取、外部数据源与系统命令函数。
- 强制追加或收紧 `LIMIT/TOP`。
- 使用数据库会话只读模式和语句超时作为第二层保护。
- 推荐数据库账号自身也仅授予 SELECT 权限。

## 5. API 与管理页面

用户接口均需要现有 Bearer session：

- `GET /data/sources`
- `GET /data/sources/{id}/catalog`
- `POST /data/query/preview`
- `POST /data/query/execute`

管理页面：`/admin/data-sources` 和 `/admin/data-permissions`。

## 6. 数据留存与审计

查询审计记录用户、数据源、操作、实际执行 SQL、表、字段、状态、行数、耗时和错误类别；不记录密码，不保存查询结果正文。

控制数据存放在管理端 `~/.agent-system/host-data/control.db`，Windows 下通过文件 ACL 加固；数据库密码还会使用当前 Windows 用户绑定的 DPAPI 加密。

## 7. 当前完成范围与后续

当前已完成数据源、结构同步、用户与用户组授权、安全查询网关、审计、用户端目录/预览/提取入口、行级范围、字段脱敏，以及查询结果自动进入加密分析附件。后续依次增加自然语言 SQL 规划、审批和查询取消。

### 用户组、行级范围与字段脱敏

- 用户可以同时获得个人权限和多个用户组权限；允许的表、字段和操作按并集合并。
- 同一张表的多条行级范围按 `OR` 合并；只要存在一条无行限制授权，该表就不再附加行条件。
- 行级条件只允许列、常量、比较、`IN`、`BETWEEN`、`IS NULL` 与 `AND/OR`，禁止函数、子查询和自行指定表名。
- 脱敏支持 `partial`（保留首尾字符）、`hash`（不可逆摘要）和 `null`（置空）。
- 脱敏字段只允许直接出现在结果列，不能用于筛选、连接、排序或计算，避免通过查询条件反推出原值。
- 若个人或任一用户组对同一字段明确授予原值访问，最终以原值权限为准；撤销个人或组权限后，下一次请求立即重新计算有效权限。

Windows 管理端安装包同时携带 Microsoft ODBC Driver 18 for SQL Server，并按微软规定在静默安装时传入许可证接受参数；官方运行时还依赖 Visual C++ Redistributable，若极少数精简系统安装失败，应先补装微软 VC++ x64 运行库。
