# Clawworker 1.7 优化开发任务

本计划按“安全与可交付 → 稳定性 → 结构拆分 → 安装包瘦身”的顺序执行。每个阶段必须通过回归测试后才能进入下一阶段。

## 阶段 1：发布完整性与安全边界

- [x] 文档正文发送前增加用户明确确认，并由后端强制校验
- [x] 审计区分结构化数据暴露与文档正文发送，审计日志不保存正文
- [x] Anthropic 改用现有 HTTP 传输，消除离线安装缺少 SDK 的问题
- [x] 桌面启动器等待 `/readyz`，503 时继续等待
- [x] 安装后真实启动管理端/用户端并验证 `/readyz`
- [x] 运行时、项目和安装包版本统一为 1.7.0

验收：相关安全、启动器、文档联合分析测试全部通过；完整测试无新增失败。

## 阶段 2：后台任务与缓存生命周期

- [x] 建立有并发上限的统一后台任务执行器
- [x] 会话分析与定时分析统一登记、排队和回收，底层模型/代码线程受总任务上限约束
- [x] 查询结果过期从“每任务一个 Timer”改为单一周期清理器
- [x] 文件夹加密缓存和代码缓存增加容量/保留期限；会话历史沿用现有条数限制

验收：慢模型、连续点击、低配置电脑压力场景中线程数有上限，取消后无遗留任务。

## 阶段 3：后端结构拆分

- [x] 管理端按用户、模型、数据源、权限、审计、运维拆分路由
- [x] 用户端 Pipeline 拆为意图、文档规则、计划、执行、结果验证五个阶段
- [x] 缩小 `client/webui/app.py`，移除已经迁移完成的兼容转发
- [x] 数据库网关分离安全规划与只读查询执行、取消、超时和容量控制

验收：外部接口保持兼容；管理端主路由由约 1510 行降至约 510 行，Pipeline 由约 1670 行降至约 1400 行；内部兼容转发已由服务层测试替代。

## 阶段 4：前端拆分与安全渲染

- [x] `app.js` 按 chat/database/tasks/settings/skills/files/api 拆分
- [x] 建立安全 DOM/Markdown 渲染工具，动态文本统一先转义
- [x] 将常用内联样式迁入共享 CSS，功能状态通过各模块工厂显式注入

验收：主脚本由 3667 行降至约 1190 行；全部脚本通过语法检查和独立模块装载烟测，模板按依赖顺序加载，动态 Markdown 默认转义。

## 阶段 5：存储、路径和错误模型

- [x] 生产 JSON、文本、证书、密文、Excel 和缓存统一使用原子写入
- [x] 集中管理用户目录、日志、缓存、输出和证书路径
- [x] 宽泛异常按网络、权限、数据、模型、取消分类
- [x] HTTP 日志和响应增加请求号与稳定错误码，查询任务沿用独立任务号

验收：模拟替换失败时旧文件保持完整且临时文件被清理；客户端与管理端响应均带请求号，错误响应带稳定代码，通用错误描述不回显原始敏感异常。

## 阶段 6：依赖和安装包精简

- [x] 拆分 common/admin/client/desktop/dev 依赖
- [x] 移除未使用的 LangGraph、开发工具；密态 SDK 明确依赖的大型分析库仅保留在用户端
- [x] 按角色打包 wheels，避免管理端和用户端互带无关包
- [x] 完成离线依赖安装、覆盖环境修复、双角色启动，以及登录、授权、数据库分析回归测试
- [x] 生成两个安装包和 SHA256 校验文件

验收：522 项自动化测试通过，5 项真实后端条件测试跳过；离线环境中管理端、
用户端均通过真实启动 `/readyz` 自检。管理端安装包由 285.7 MB 降至 71.1 MB，
用户端由 453.2 MB 降至 422.2 MB；大型分析依赖属于 HE SDK 的声明依赖，因此只在
用户端保留。两个 1.7.0 安装包已实编译并生成 SHA256 校验文件。
